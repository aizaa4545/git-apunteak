1. Zer da Git?

Git bertsio-kontrolerako sistema bat da. Programa edo proiektu baten fitxategietan egindako aldaketak gordetzeko eta haien historia ikusteko erabiltzen da.

Git erabiliz, aurreko bertsio batera itzul gaitezke, zer aldatu den ikus dezakegu eta hainbat pertsonak proiektu berean lan egin dezakete.

Adibidea: HTML fitxategi batean aldaketa bat egiten baduzu, Git-ek aldaketa hori gordetzeko aukera ematen dizu. Gero, nahi baduzu, aurreko egoera berreskura dezakezu.

Git eta GitHub ez dira gauza bera

  • Git: zure ordenagailuan erabiltzen den bertsio-kontrolerako programa.
  • GitHub: Git proiektuak Interneten gordetzeko eta besteekin partekatzeko web-plataforma.

2. Oinarrizko kontzeptuak

  • Repository (biltegia): Git-ek kontrolatzen duen proiektuaren karpeta.
  • Commit: une jakin bateko aldaketen argazkia edo gordeketa. Mezu bat izaten du aldaketak azaltzeko.
  • Working directory: lanean ari zaren fitxategien karpeta.
  • Staging area: hurrengo commit-ean sartuko diren aldaketak prestatzeko eremua.
  • Branch (adarra): proiektuaren lan-lerro independente bat. Ezaugarri berri bat probatzeko erabil daiteke.
  • Remote: urruneko biltegia, adibidez GitHub-en dagoena.

Git-en hiru egoera nagusiak

  1. Working directory: fitxategiak aldatu dituzu.
  2. Staging area: git add erabiliz aldaketak aukeratu dituzu.
  3. Repository: git commit erabiliz aldaketak historian gorde dituzu.

4. Ohiko lan-prozesua

Proiektu batean aldaketak egin eta Git-en gordetzeko, normalean pauso hauek jarraitzen dira:

git status
git add .
git status
git commit -m "HTML orria gehitu"
  1. Fitxategiak sortu edo aldatu.
  2. git status erabili zer aldatu den ikusteko.
  3. git add . erabili aldaketak prestatzeko.
  4. Berriro git status erabili dena ondo dagoela egiaztatzeko.
  5. git commit -m "..." erabili aldaketak gordetzeko.
Gogoratu: git add-ek ez ditu aldaketak behin betiko gordetzen. Commit-a egiteko git commit ere erabili behar da.

5. Adarrak (branches)

Adarrek proiektuaren kopia independente batean lan egitea ahalbidetzen dute. Horrela, ez dugu proiektu nagusia zuzenean aldatu behar.

git branch
git branch diseinu-berria
git switch diseinu-berria
git switch main
  • git branch: dauden adarrak erakusten ditu.
  • git branch diseinu-berria: adar berria sortzen du.
  • git switch diseinu-berria: adar horretara aldatzen da.
  • git switch main: main adarrera itzultzen da.

Merge: adarrak elkartzea

Adar batean egindako lana beste adar batean sartzeko, adibidez main-en:

git switch main
git merge diseinu-berria

Batzuetan merge conflict bat ager daiteke: bi adarretan lerro berak modu desberdinean aldatu direnean. Fitxategia eskuz zuzendu eta ondoren commit egin behar da.

6. .gitignore fitxategia

.gitignore fitxategiak Git-ek jarraitu behar ez dituen fitxategiak edo karpetak adierazten ditu.

Adibidez, aldi baterako fitxategiak edo sortutako karpetak baztertzeko erabil daiteke:

bin/
obj/
*.tmp
.DS_Store

7. GitHub-ekin lan egitea

GitHub-en biltegi bat sortu ondoren, zure ordenagailuko biltegia harekin konekta dezakezu:

git remote add origin https://github.com/erabiltzailea/proiektua.git
git branch -M main
git push -u origin main

Ohiko erabileran:

  • git pull: lehenik besteen azken aldaketak jaso.
  • Aldaketak egin eta commit-ak sortu.
  • git push: zure aldaketak GitHub-era bidali.
